# dumbbell

周期的に幅が変化する2次元チャネル内で、電気双極子の性質を持つ棒状粒子(ダンベル型粒子)が行うブラウン運動を数値シミュレートするプログラムです。一定の外力と一定の電場のもとでの平均初通過時間・非線形移動度・有効拡散係数を、GPU(CUDA)を用いた大規模アンサンブル計算で求めます。

物理モデルの詳細は [docs/model.md](docs/model.md) を、計算機環境は [docs/architecture.md](docs/architecture.md) を参照してください。

## 必要環境

- Rust(edition 2024)
- CUDA Toolkit 12.x(`nvcc` が必要)と NVIDIA GPU — 既定のGPUビルドの場合
- GPUがない環境では CPU 版としてビルド可能です(後述)

## 使い方

### 1. 設定ファイルを書く

シミュレーションの定数はすべて TOML ファイルで指定します。リポジトリ直下の [config.toml](config.toml) が設定例です。

```toml
delta_t = 2e-7        # 時間刻み幅 Δt
time = 10.0           # 総シミュレーション時間 T
k = 1.5e6             # 壁のばね定数 K
ensemble_size = 30000 # 1ケースあたりの粒子数
output_dir = "data/example" # 結果をまとめて出力するフォルダ

# 以下の4つはリストで指定し、その全組み合わせ(直積)が実行される
f   = [10.0, 20.0, 30.0] # 一定外力(x方向)
c_1 = [0.0, 5.0]         # 電場パラメータ C1 = βEp/l̃
c_2 = [0.0]              # 電場パラメータ C2 = ΔαE/p
l   = [0.05, 0.1]        # 棒の長さ

[gpu]                  # 省略可
# ids = [3, 1, 2, 0]   # 使用するGPU(省略時は全GPU)
# tasks_per_gpu = 4    # GPUあたりの同時実行ケース数(省略時は実測に基づく既定値4)
```

### 2. シミュレーションを実行する

```sh
cargo run --release                          # ./config.toml を使って全ケースを実行
cargo run --release -- --config sweep.toml   # 設定ファイルを指定して実行
```

ケースは全GPUのワーカーに自動的に振り分けられ、終わったものから順に結果が書き出されます。

### 3. 結果を見る

`output_dir` に次の構造で出力されます。

```
data/example/
├── config.toml               # 使用した設定ファイルのコピー(再現用)
├── summary.dat               # 全ケースのまとめ(1ケース1行)
│                             #   列: f c_1 c_2 l mean_disp mu d_eff mfpt
├── f10_c1-0_c2-0_l0.05/      # パラメータの組ごとのフォルダ
│   ├── config.toml           # このケースの全パラメータとシード(単独で再現可能)
│   └── result.dat            # このケースの統計量
└── f20_c1-0_c2-0_l0.05/
    └── ...
```

各統計量の意味:

| 列 | 意味 |
| --- | --- |
| `mean_disp` | 平均変位 ⟨Δx⟩ |
| `mu` | 非線形移動度 μ = ⟨v⟩ / f |
| `d_eff` | 有効拡散係数 D_eff = (⟨Δx²⟩ − ⟨Δx⟩²) / 2T |
| `mfpt` | 平均初通過時間(周期1を進む平均時間)= 1 / \|⟨v⟩\| |

各ケースの乱数シードはパラメータの組から決定論的に導出されるため、同じ設定からは常に同じ結果が得られます(GPUでの総和の加算順序に由来する最下位桁程度の揺らぎを除く)。

### 4. アニメーションを見る

```sh
cargo run --release -- animate
```

1粒子の運動をリアルタイムに描画します。初期パラメータには設定ファイルの各リストの先頭値が使われます。

- **seed / f / C1 / C2 はGUIで変更可能**。f, C1, C2 は実行中の粒子に即座に反映され、seed は Reset ボタンを押したときに反映されます
- 初期状態(灰色の棒)と現在の状態(赤い棒。黄色い点が + 端)が同時に表示されます
- カメラは x 方向にのみ粒子を追いかけます。デッドゾーン+一次遅れ平滑化により、ブラウン運動の細かな揺れで画面がガタつかないようになっています

## CPU版としてのビルド

GPUがないマシンでは、同じ物理モデルのCPU実装(rayon並列)で動かせます。小規模な動作確認・検証用です。

```sh
cargo run --release --no-default-features
```

CPU実装(`src/simulation.rs`)とGPU実装(`src/simulation.cu`)は同一の物理モデルを実装しており、両者の統計量が一致することを検証済みです。物理モデルを変更する際は必ず両方を同期させてください。

## プロジェクト構成

```
src/
├── main.rs        # CLI(run / animate サブコマンド)
├── config.rs      # TOML設定の読み込みとパラメータ組み合わせへの展開
├── simulation.rs  # 物理モデルのCPU実装(アニメーションとCPU版で使用)
├── simulation.cu  # 物理モデルのGPU実装(CUDAカーネル)
├── runner.rs      # 全ケースの実行と結果の書き出し(GPU/CPUバックエンド)
└── renderer.rs    # アニメーション表示(egui/eframe)
docs/
├── model.md       # 物理モデルの導出と定式化
└── architecture.md# 実行マシンのハードウェア構成
```

## 性能メモ(NVIDIA A100での実測)

- 1カーネル(1ケース、3万粒子)ではA100を使い切れないため、**GPUあたり4ケースを別ストリームで同時実行**して飽和させています(`tasks_per_gpu` の既定値)
- 飽和スループットはA100 1枚あたり約 1.3×10¹⁰ 粒子ステップ/秒。標準設定の1ケース(3万粒子 × 5×10⁷ステップ)は4GPUのマシン全体で実効約30秒に相当します
- ブロックサイズ128・cuRAND XORWOW の採用も同実測に基づく選択です(いずれも256・Philoxより数%〜十数%高速)
